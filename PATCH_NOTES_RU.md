# Исправления MVS Analyzer 1.4.0

## Что находится в архиве

Это исправленный проект **с исходным кодом**, двумя обновлёнными ноутбуками и скриптом сборки. Готовый EXE в исходном архиве отсутствовал; в этом архиве EXE тоже не заявлен. Версия приложения остаётся **1.4.0**, движка — **1.6.0**.

## Что исправлено

1. Вместо вкладки Google Colab — отдельное немодальное окно Windows в стиле MVS. Есть калибровка, анализ, остановка, скачивание, состояние, прогресс и подключение. Повторный вызов поднимает существующее окно. Переключение страниц его не уничтожает.
2. Дополнительные команды и восстановление вынесены в «Ещё». Нет пятнадцати кнопок, разбросанных по широкой странице. Кнопки недоступных действий отключены, причины объясняются состоянием подключения.
3. Исправлена отправка variance/MELSM/estimation/benchmark: тип задания больше не передаётся вместо команды контроллера.
4. Остановка/скачивание старого облачного задания не блокируются из-за новых данных, открытых локально. Полученные облачные файлы не меняют состояние выполняющегося локального расчёта; их можно открыть через «Ещё» после завершения.
5. Кнопки на существующих страницах измеряются по тексту, имеют одинаковую высоту в строке и при необходимости переносятся. В частности, исправлено несоответствие «Новый проект» / «Демонстрационный пример».
6. Убрано отключение всей managed-формы на время калибровки, анализа, дополнительных методов и бенчмарка — причина потемнения текста. Используется стандартное модальное блокирование Windows. Окно прогресса и неактивные кнопки сохраняют выбранную палитру. Поздние сообщения прогресса не обращаются к уничтоженному окну.
7. В ноутбуке отображаются фактически обнаруженные CPU/RAM/GPU; подготовку CLI в режиме управления можно отменить. Старые проверенные калибровки не удаляются, версия протокола совместима.

## Что намеренно НЕ обещается

- **Смена ускорителя не автоматизирована.** Нажмите «Среда выполнения…» и подтвердите выбор в официальном интерфейсе Colab. Нынешний мост не предоставляет список доступных вашему аккаунту GPU/TPU и не переключает виртуальную машину. Фиктивного списка ускорителей нет.
- Этот движок MVS вычисляет на CPU. Выбор GPU/TPU не добавляет ускорение сам по себе.
- Первое подключение всё ещё требует открыть ноутбук, запустить первую ячейку и вставить код. Дальнейшие команды отправляются из отдельного окна. Браузер может запросить доступ к локальной сети.
- Закрытие окна Colab не означает отмену расчёта. Для отмены нажмите «Остановить». Закрытие всего приложения не выключает облачную среду Google.

## Как собрать и запустить

1. Полностью распакуйте архив в отдельную папку. Сохраните старую рабочую сборку отдельно для отката.
2. На Windows установите **.NET SDK 8** (для сборки нужен SDK, а не только Runtime).
3. Запустите `build_release.bat`. Он собирает самодостаточный Windows x64 EXE. Путь результата: `bin\Release\net8.0-windows\win-x64\publish`.
4. Для Colab используйте `notebooks/MVS_Colab.ipynb` из этого архива, а не старую копию на Drive. Сохранить его также можно через «Ещё → Сохранить ноутбук этой версии…». Откройте его в Colab через загрузку и сохраните адрес своего ноутбука в окне подключения.
5. На странице калибровки/анализа нажмите «Запустить через Colab», подтвердите передачу задания и подключите первую ячейку. После подключения пользуйтесь отдельным окном.

## Что проверено в среде подготовки

- 62 офлайн Python-теста: 21 исходный тест обмена/проверки файлов, 21 тест контроллера, 6 тестов проверки исходников, 14 новых тестов исправлений. Часть тестов — статические контракты C#; это не выполнение WinForms.
- Синтаксис Python и встроенных ячеек, воспроизводимость обоих ноутбуков, точное соответствие встроенного ZIP исходникам CLI, метаданные проектов, ссылки README, защищённые изображения/плагины и хеши формулы.
- 34 файла Core/Infrastructure/Benchmark/CLI, общего реестра и проектов побайтно совпадают с присланным архивом. Пины: `validation/ui-patch-baseline.json`.
- Ограниченная структурная проверка C# (баланс скобок и расположение исходников), **не компиляция**.

**Не выполнено здесь:** сборка .NET, запуск WinForms на Windows, проверка DPI на реальных мониторах и подключение к вашему аккаунту Colab. В среде нет .NET SDK/Windows; загрузка SDK недоступна. Поэтому успешная нативная сборка и отсутствие всех UI-регрессий не заявляются.

## Как выполнить нативные проверки

На Windows из папки проекта:

```bat
dotnet build MvsAnalyzer.csproj -c Release
dotnet run --project MvsAnalyzer.Tests/MvsAnalyzer.Tests.csproj -c Release
dotnet run --project MvsAnalyzer.Core.Tests/MvsAnalyzer.Core.Tests.csproj -c Release
dotnet run --project MvsAnalyzer.Ui.Tests/MvsAnalyzer.Ui.Tests.csproj -c Release -- artifacts/ui-layout
```

UI harness проверяет страницы RU/EN, светлую/тёмную тему, размеры окон, вложенные кнопки, отдельное окно Colab в разных состояниях, отсутствие второй копии, сохранение при навигации, прогресс и отмену. Он сохраняет настоящие снимки WinForms для визуального просмотра. Дополнительно проверьте масштаб Windows 100/125/150/200%, смену темы с открытым Colab и полный цикл живого ноутбука: подключение → калибровка → анализ → скачивание → остановка/переподключение.

Для офлайн-проверок нужен Python 3.10+:

```bat
python tools/check_source.py
python tools/build_notebooks.py --check
python tools/build_colab_payload.py --check
python tools/test_colab.py
python tools/test_colab_control.py
python tools/test_source.py
python tools/test_ui_patch.py
python tools/check_csharp_structure.py
```
