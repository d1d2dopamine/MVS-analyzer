# Round36: старые файлы больше не приписываются новому успешному запуску

## Исправленная ошибка

При `--overwrite` MVS разрешает использовать непустую папку. Раньше после успешного расчёта манифест и машинный JSON перечисляли все файлы этой папки. Поэтому старый посторонний отчёт получал корректный хеш, но ошибочно считался результатом текущего запуска.

Отрицательный пример сохранён: реальный CLI завершился с кодом 0, а неизменённый старый файл размером 164 байта оказался в обоих списках. При этом три новых научных файла полностью совпадали с чистым контрольным запуском. То есть найденная ошибка касалась принадлежности результатов, а не изменения вычисленных чисел. Дополнительно воспроизведено присвоение старого runId из чужого манифеста.

## Что изменилось

- Манифесты variance, estimation и MELSM перечисляют ровно три файла, записанные этой командой. Это работает и без машинного JSON.
- Для команд с учётом записей успешные, диагностические и ошибочные машинные результаты используют проверенный список текущих записей. Старый манифест не подхватывается только потому, что лежит рядом.
- Добавлено поле `artifactScope: current_invocation_successful_writes`. Python при таком явном контракте ищет и копирует только перечисленные файлы, проверяет их путь, размер и хеш. Старые файлы и вложенные папки не копируются автоматически. Неизвестная область или повреждённое описание отвергаются.
- Старые файлы не удаляются. Старые движки без нового поля сохраняют прежний контракт совместимости.
- Проверенная ревизия исходника добавлена отдельным слоем v3: предыдущие исторические хеши и четыре старых пробела происхождения не переписаны. Встроенный исходник Colab пересобран официальным генератором.

## Проверки

Окончательная сводка: `../validation/round36-results.json`. Сырые результаты, прежние сбои, команды и независимая проверка: `../validation/round36-evidence.zip`.

Фактически уже выполнены: 21 сценарий нового нативного сравнения, 44 проверки сохранённых результатов, их искажений и маршрутизации CI; 195 существующих нативных проверок, 14 проверок частичного вывода, 26 проверок вывода после восстановления. В новых реальных запусках estimation и variance завершились с кодом 0; MELSM сохранил диагностический код 2. Старые файлы остались неизменными; новые научные файлы чистого и загрязнённого запусков побайтно совпали. Чистый estimation также побайтно совпал между старой и новой версией.

Финальная Python-проверка: 154 теста, 140 пройдены и 14 пропущены как требующие настоящей Windows. Реальный Linux MCP-обмен с нативным движком выполнен успешно. Из них 34 новых целевых Python-проверки также независимо повторены без пропусков. Общая валидация: 479 тестов, 478 пройдены; один тест старого resume-контрпримера пропущен, поскольку текущая повторная проверка запускалась только с исправленным движком. Сам прежний отрицательный пример сохранён в исторических материалах.

Другие инструментальные проверки: 152 пройдены. Цепочка хешей: 43/43, Colab: 48/48, UI: 18/18; независимо повторены. Новый нативный CI-режим без старого бинарника: 19/19; проверка его сохранённых результатов: 42 пройдены и один ожидаемый baseline-only пропуск. Точная проверка встроенного исходника, CLI-контракта и ноутбуков проходит. Итоговый полный ZIP дополнительно проверяется после свежей распаковки; её журнал и хеш архива передаются при сдаче.

Финальная проверка workflow выявила ещё один сборочный дефект: отрицательные тесты специально создают повреждённые манифесты и каталоги вместо файлов, а общая проверка успешно сохранённых результатов рекурсивно обходила ту же папку. Три набора отрицательных примеров теперь пишутся в отдельную загружаемую папку regression-evidence; строгая проверка обычных artifacts не ослаблена. Старые отказы обоих наборов и нового набора сохранены. Проверка обычных сохранённых calibrate/analyze-артефактов при соседних отрицательных примерах проходит. Полный удалённый GitHub workflow здесь не запускался.

Один ранний сборочный запуск нового тестового harness выявил опечатку объявления C#; она исправлена до выполнения тестов. Это не отказ производственного расчёта. Все полученные отрицательные примеры сохранены.

## Ограничения и откат

Это учёт отдельных завершённых записей, а не атомарное сохранение всей папки. Одновременно изменённый файл может быть исключён после повторной проверки; копирование при последующем сбое может оставить неполную новую папку. Для нового Python-контракта нужны пути без символьных ссылок и Windows reparse points в родительских каталогах, как для чтения/повторного использования Calibration, так и для копирования. Например, алиасы `/tmp` или `/var` на macOS могут быть отвергнуты: используйте настоящий путь. Это более строгая проверка; реальное macOS/Windows-выполнение здесь не подтверждено.

Наличие списка не доказывает, что владелец машины не менял историю.

Неинструментированный старый benchmark-экспорт и state-check сохраняют свой прежний контракт. Манифесты восстановленных расчётов по-прежнему создаются внутри новой дочерней папки; они не переработаны в защиту от стороннего одновременного добавления файлов. Старый Python с новым движком сам не приобретает новый безопасный способ копирования: обновлять следует весь проект.

Математика, случайные последовательности и checkpoint-вычисления не менялись; 24 файла Core/Benchmark побайтно совпадают с Round35. Статистические эксперименты R27/R32 не активированы, научный NO-GO остаётся. Windows в этой среде не запускалась.

Откат: восстановить полный исходный Round35 и соответствующую Python-обёртку, не изменяя пользовательские данные. Полный ZIP Round36 содержит необходимые исходники, тесты, workflow и встроенный Colab-архив; старые патчи для сборки не нужны. Необязательные большие исторические материалы отмечены в корневом манифесте архива.
