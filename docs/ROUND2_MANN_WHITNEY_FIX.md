# Round 2 numerical repair: Mann-Whitney normal-CDF precision

Date: 2026-10-11. Base: the delivered round 2 source archive. The owner supplied
a native CI log with 87/88 passing tests; the sole failure was `mw_overlap` in
the new Mann-Whitney reference group. The log establishes that the previous
source compiled and its tests executed; it does not validate this repaired
source or a real CLI/Python run.

## Cause and correction

The asymptotic Mann-Whitney routine already computes tied ranks, the tie
variance correction and the two-sided continuity-corrected normal statistic.
The failure was in its private normal-CDF approximation: its polynomial
coefficients had been rounded to seven decimal places. That rounded variant
does not meet the independently declared absolute p-value accuracy gate.

The repair retains Abramowitz-Stegun 26.2.17 and restores its full published
coefficient precision:

| Coefficient | Previous | Repaired |
| --- | ---: | ---: |
| b1 | 0.3193815 | 0.319381530 |
| b2 | -0.3565638 | -0.356563782 |
| b3 | 1.781478 | 1.781477937 |
| b4 | -1.821256 | -1.821255978 |
| b5 | 1.330274 | 1.330274429 |

The density factor is computed as `exp(-z*z/2)/sqrt(2*pi)` rather than using a
decimal truncation of `1/sqrt(2*pi)`. See the original
[Handbook, page 932, formula 26.2.17](https://personal.math.ubc.ca/~cbm/aands/page_932.htm).
Its CDF error bound is below 7.5e-8 for the published approximation; a two-sided
p-value doubles CDF error. The fixed native `2e-7` gate remains unchanged.

## Identity and compatibility

The numerical engine advances from `1.6.0` to `1.6.1`, because its p-values can
change. The application version remains `1.4.0`. Formula `MVS-1.4.0`, its hash,
the twelve-metric registry, Bonferroni multiplier, rank-test sidedness/tie/
continuity settings, unavailable policies and public schemas are preserved.

Existing engine compatibility checks reject old `1.6.0` calibration and backup
states; `--force` cannot bypass method incompatibility. Recalibrate from the
original input into a new folder with engine `1.6.1`. A native regression now
explicitly checks rejection of a saved `1.6.0` calibration. Old results and
benchmark history are retained as old-engine evidence, not recomputed in place.

The engine metadata in the CLI contract, output checker, structured identity
test, method metadata, Colab helper, notebook builders and embedded-source
builder is synchronized. The source payload and both Colab notebooks are
regenerated by their existing builders. The explicit Core byte pins record the
authorized numerical repair/version identity; their historical original pins
are retained. This avoids disguising changed arithmetic under an old identity.
