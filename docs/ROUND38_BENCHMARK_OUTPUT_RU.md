# Round38: происхождение файлов benchmark и его восстановления

## Зачем это исправление

При ошибке сохранения benchmark мог уже записать часть отчёта, но JSON для
Python/агента сообщал пустой список файлов и не называл папку. При успешном
экспорте посторонний файл, появившийся в этой папке, попадал в машинный список
результатов. В восстановленном benchmark такой файл попадал ещё и в обновлённый
список SHA256SUMS, включая вложенные папки.

Это воспроизведено на неизменённом Round37 с заранее сохранённым синтетическим
завершённым результатом. Научные симуляции не запускались. Benchmark создаёт
новую уникальную папку: обычное повторное использование старой папки через
`--overwrite` здесь **не доказано**. Контрольный посторонний файл добавлялся
синхронно в ходе экспорта. Это проверка принадлежности файлов запуску, а не
доказательство защиты от владельца компьютера, который меняет данные.

## Что меняется

- Каждый известный файл отчёта отмечается перед записью и после успешной записи.
  CLI сообщает завершённые файлы и незавершённую запись даже при ошибке.
- Успешный benchmark использует существующий контракт
  `artifactScope=current_invocation_successful_writes`; посторонние файлы
  остаются на диске, но не объявляются результатами запуска.
- Восстановление использует настоящую внутреннюю папку `MVS_Benchmark_*`,
  а не окружающую папку `MVS_restored_*`.
- Обновлённый SHA256SUMS строится из явно записанных файлов отчёта, возвращённых
  графиков и `backup_resume.json`, без обхода содержимого папки.
- Первоначальный SHA256SUMS исключается из завершённых результатов **до**
  добавления сведений о восстановлении. Если дальнейшая запись не удалась,
  оставшиеся старые байты не объявляются актуальным завершённым контрольным
  списком. Перед окончательной записью путь снова отмечается как текущая попытка.
- Сообщение об отмене больше не обещает, что ничего не было записано.

Старые программные точки входа сохранены. Их обёртки вызывают новую реализацию
без наблюдателя. Формулы, генератор случайных чисел, параметры benchmark,
порядок вычислений, готовые результаты и правила восстановления вычислений
не изменены. Успех/диагностический результат/ошибка сохраняют коды 0/2/1.

## Границы гарантии

Запись не стала транзакцией: при ошибке файл может быть частично изменён,
а предыдущий контрольный список может физически остаться на диске. Он не
объявляется проверенным результатом текущего запуска. Ручному читателю нужно
учитывать ошибку, машинному клиенту — статус и список артефактов.

Старый интерфейс рисования сообщает пути только после успешного возвращения
генератора. Если генератор графиков сам выбросил исключение, его неизвестные
частичные файлы нельзя восстановить из этого интерфейса. Headless CLI не
передаёт такой генератор. Наблюдатель не обеспечивает защиту от параллельной
подмены файлов владельцем компьютера.

Это исправление надёжности и происхождения результатов, без заявлений о росте
статистической точности или скорости. Научный NO-GO сохраняется. Эксперименты
Round27 и Round32 не активированы. Повторная проверка Windows остаётся отдельной
и не заменяется успешной сборкой или Linux-тестами.

## Проверка и поставка

Проверено на Linux / .NET 8.0.31:

- На исходном Round37: 10 контрольных случаев подтверждают старое поведение.
  Отдельная первая репродукция и все её файлы также сохранены.
- На исправленном коде: 26/26 экспортных случаев. Это настоящие CLI-вызовы и
  отдельно обозначенные вызовы API с управляемыми сбоями, включая отмену после
  первой записи, ошибки manifest/SHA256SUMS и возвращённый генератором график.
- 68/68 полных файлов в пяти чистых парах Round37/38 совпали побайтно, без
  исключения или нормализации полей. Входные контрольные точки не изменились.
- 19/19 проверок сохранённого экспортного свидетельства, включая испорченные
  примеры. Отсутствующий явно заданный отчёт приводит к ошибке, не к пропуску.
- 195/195 существующих native-проверок; прежние экспортные наборы: 14/14,
  26/26 и 19/19. Python: 140 пройдено, 14 Windows-проверок пропущено на Linux;
  настоящий Linux native MCP-тест выполнен.
- Общий набор validation: 496 пройдено, 2 прежние проверки сравнения со старым
  бинарником пропущены, поскольку для этих двух старых наборов здесь повторно
  запускался только текущий кандидат. Новый benchmark сравнен с Round37 явно.
- Защищённые исходники: 64/64 проверки обычно и с `python -O`; Colab 48/48;
  UI-структурные 18/18; организация/миграция корня 59/59. Новая v4-запись
  фиксирует два проверенных изменения benchmark, не переписывая старые якоря.
- Встроенный исходный Colab-пакет пересобран штатным генератором. Проверены
  `check_source.py`, CLI-контракт, notebooks, структурные и независимые
  математические проверки. Это не запуск всего удалённого GitHub Actions.

Подробности и машинные итоги: `validation/round38-results.json`;
сырьё, прежние неудачные попытки и независимый разбор:
`validation/round38-evidence.zip`. Первая попытка запустить новый контракт на
старом бинарнике без флага baseline ожидаемо не прошла; она сохранена отдельно
и не выдаётся за успешный baseline. Полный ZIP сохраняет структуру Round37 и
инструкцию `packaging/README_RU.md` для старых корневых копий через обратимый перенос.

В CI добавлен отдельный запуск `validation/benchmark_export_contract`; его
отрицательные примеры лежат в `regression-evidence/benchmark-export`, отдельно
от настоящих экспортов, проверяемых рекурсивно через `check_outputs.py artifacts`.
Новый результат не меняет численные критерии готовности проекта.
