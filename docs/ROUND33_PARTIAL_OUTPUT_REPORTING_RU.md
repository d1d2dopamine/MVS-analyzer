# Round33: что сохранилось после ошибки экспорта

## Результат

Исправлена воспроизведённая ошибка интерфейса: если первый файл успевал сохраниться, а следующий записать не удавалось, CLI возвращал ошибку с пустым списком файлов и без каталога результата. Теперь он сообщает, какие файлы действительно записаны этим запуском и ещё проходят проверку хеша, а какой файл остался неопределённым. Весь запуск по-прежнему считается неудачным.

Это полезно для человека, Python и локального ИИ-агента: можно понять, что осталось после сбоя, не принимать старые файлы из той же папки за новые результаты и не запускать анализ автоматически ещё раз.

## Как проверена ошибка

Тест запускает настоящий CLI на небольшом искусственном наборе. Сразу после проверки выходного каталога он создаёт препятствие: каталог с именем следующего CSV. Первый `calibration.csv` успевает записаться, второй экспорт падает. У Round32 ответ скрывает сохранившийся файл; Round33 возвращает его точный размер и SHA256. Его 4 770 байт одинаковы до и после исправления. Отдельно проверен сбой записи итогового manifest через настоящий экспортёр.

Во время проверки нового Python-интерфейса найден и закрыт связанный риск: неудачный объект калибровки мог указывать на папку со старым файлом состояния. Теперь такой объект нельзя передать в `analyze`; новый процесс даже не запускается. Неудачный результат также нельзя скопировать целиком через `copy_to`, а поиск файла не подбирает неуказанные старые файлы.

## Границы изменения

- Охвачены `calibrate`, `analyze`, `variance`, `estimation`, `melsm`.
- Ошибка остаётся `exitCode=1`, `status=error`; сохранённый отдельный файл не означает завершённый анализ.
- Неизменённые старые файлы и старый manifest не объявляются результатами текущего запуска. Неопределённый целевой файл не считается успешно записанным.
- Python-исключение предоставляет проверенный ответ через `exc.result`. Локальный MCP сохраняет только безопасные имена, размеры и хеши частичных файлов, без абсолютных путей; повторный запрос возвращает прежнюю ошибку, не повторяет вычисление.
- Это не транзакционная запись всех файлов и не обещание восстановления после любого аварийного завершения. Проверка файлов относится к моменту формирования ответа.
- `benchmark`, `resume`, архивный desktop и файлы плагина, который сам завершился исключением, остаются отдельными границами. Для трёх научных команд напрямую не внедрялась поздняя ошибка записи: проверены общий механизм отслеживания, реальный CLI калибровки, реальный экспортёр и успешные выходы всех пяти команд.

Статистические вычисления, 12 метрик, поправка Bonferroni и научный NO-GO не изменены. Не активированы ни эксперимент Round27, ни замена Math.NET из Round32.

## Выполненные проверки

- Основная native-suite: **195/195**.
- Новая native-проверка: **14/14** для текущей версии; **16/16** вместе с двумя контрольными проверками старой версии. В них ожидаемая старая ошибка сохранена как отрицательный контроль.
- Актуальные Python/tool-suite: **619 обнаружено, 605 успешно, 14 пропущены** только из-за отсутствия настоящей Windows-среды. Общий запуск прошёл с 617 тестами; после добавления ещё двух проверок самого валидатора повторена вся validation-suite: 347/347. Остальные файлы тестов не менялись.
- Включены настоящий Linux native MCP wire-test, 18 новых Python/API/MCP проверок и 22 проверки сохранённых native-доказательств. Независимый повтор 18 и 22 проверок также успешен.
- Сборка CLI Release: 0 предупреждений, 0 ошибок.
- Добавлен запуск нового native-harness и проверки его отчёта в обычный CLI CI. Этот workflow локально не публиковался и удалённо не запускался.
- Windows runtime остаётся ожидающей проверкой владельца. Linux и синтетические Windows-ветки её не заменяют.

## Сравнение с Round32

План `validation/round33-plan.json` зафиксирован до измерений. Выполнены ровно 30 новых процессов: по три пары AB/BA/AB для пяти команд. Все исходные ответы и файлы сохранены. Научные JSON/CSV совпали точно, без допуска для чисел; исключены только заранее перечисленные временные метки, идентификаторы и пути. Все 150 хешей/размеров файлов и связи manifest проверены отдельно. 24 процесса завершились кодом 0; шесть ограниченных MELSM-прогонов получили заранее разрешённый код 2 и одинаковый `not_converged`. Это инженерное сравнение, не новая проверка научной валидности.

Измерения: 2026-10-16 17:15:12–17:15:35 UTC, два CPU, резервное копирование выключено, параллельных тестов в этом окне не было.

### Ограничение измерения времени

После запуска обнаружено, что драйвер опрашивает завершение процесса каждые 50 мс. Поэтому сохранённое wall-time включает задержку обнаружения и не показывает точный момент завершения. Разница в несколько миллисекунд не интерпретируется как ускорение или замедление. Исходный драйвер, план и все 30 результатов оставлены без изменения; повторные удобные измерения не подбирались. CPU-время и максимальная память взяты из kernel `wait4` для конкретного процесса и не включают эту задержку родительского опроса. Три пары всё равно дают только описательное сравнение.

## Доставка и откат

Передаётся полный исходный ZIP Round33, не патч. Для сборки предыдущие архивы не требуются. Сохранены обновлённый публичный корневой README и локальный индекс документации; подробные технические отчёты размещены в docs. Большой необязательный архив сырых данных Round27 по-прежнему вынесен отдельно; он не нужен для сборки/CI. Полные измерения Round31/32 также остаются отдельными материалами аудита.

Для отката используйте сохранённый полный Round32 и пересоберите приложение; не смешивайте старые и новые сборки. Round33 не меняет формат калибровок, версии научных формул или результаты завершённых вычислений.
