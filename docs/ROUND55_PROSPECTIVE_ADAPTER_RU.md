# Round55: проверка исполнителя и инженерная оценка стоимости

## Результат

Подготовлен изолированный исполнитель для одного заранее заданного примера будущего сравнения методов. Все 11 запусков завершились; каждый точно воспроизвёл полный результат и 1103 записи промежуточных вычислений двух сохранённых эталонных запусков. Ошибок, замен запусков и повторных попыток не было. Это полезный шаг к запуску нового статистического бенчмарка: теперь проверены связь с настоящим движком, полнота вычислений, воспроизводимость и измерение ресурсов.

Новых статистических наборов данных не создавали. Значения ложных срабатываний и мощности из прежних исследований не изменились; новые значения здесь не оценивались. Производственные алгоритмы, версии, интерфейсы, README и исторические результаты сохранены.

## Что именно проверено

Протокол `MVS-PROSPECTIVE-ADAPTER-COST-1.0.0` фиксирует три последовательных запуска и затем восемь параллельных, максимум 300 секунд и 2 GiB суммарной наблюдаемой памяти. Каждый процесс использует один закреплённый CPU и .NET 8.0.31. На каждом запуске настоящий Core выполняет полный расчёт вариационных компонент и исходных 12 сводных показателей на одном неизменном примере: две группы по 16 объектов, по 40 наблюдений, всего 1280 строк. Внутренние bootstrap-вычисления действительно выполняются; отсутствие новых данных относится к внешним наборам будущего исследования.

Выполнены 11 × 1103 = 12 133 проверки упорядоченных записей вычислений против каждого из двух старых запусков. Допуск численного расхождения равен нулю; единственное исключение в сравниваемом содержимом — номер старого вызова. Проверены хеш данных, весь отчёт, результаты исходного метода, полнота, отсутствие восстановления из кеша, конечные значения и сходимость. Хеш означает контрольный отпечаток байтов файла.

Старый файл вспомогательного исполнителя позднее получил дополнительные функции для другого исследования. Это раскрыто в контракте: удаление только тех добавлений восстанавливает старый файл побайтно; используемые функции и остальные 13 исходных ресурсов совпадают. Мы не утверждаем тождество целых исторического и нового исполняемых файлов.

| Расчётная потребность хранения по замороженной формуле | 16 116 605 824 байта |
| Доступное место при проверке | 25 170 853 888 байт |

Заранее заданная формула `2 × max(самый медленный последовательный вызов, время параллельного пакета) × 12000 / 8` даёт 1.90 часа. Это оценка по одному простому фиксированному примеру. Сохранённая линейная оценка по реальному предыдущему исследованию из 192 наборов остаётся **11.59 часа**. Разница не означает ускорения метода: разные данные требуют разного количества работы оптимизатора. Обещать завершение полного исследования за 1.90 часа нельзя.

Проверка ресурсного допуска этого примера пройдена. RSS измерялась каждые 50 мс; краткий пик между измерениями возможен. Ограничение объёма вывода также наблюдаемое, не системная квота: превышение сохраняется и делает допуск отрицательным. Это не доказательство максимальной стоимости произвольных будущих данных.

## Проверки программного контракта

- Новый validation-only проект собран: 0 предупреждений, 0 ошибок.
- Проверены identity и 54 случая проверки запроса, окружения и контрольного отпечатка (2 допустимых, 52 отклонённых); вычисления модели не начинались.
- Независимая проверка: 40 тестов исполнителя и 2 статических теста native-контракта пройдены. Проверяются повреждение результатов, пропуски/дубли/перестановка записей, таймауты, дерево процессов, ошибки памяти/вывода и подмена исходников.
- Полный набор validation: 926 выполненных тестов, из них 923 пройдены и 3 пропущены; отдельно пропущены 4 класса, которым нужны внешние сохранённые материалы. Два новых native-теста в общем прогоне пропущены без пути к сборке, но отдельно выполнены на настоящей сборке; оставшийся пропуск существовал ранее.
- Python API: 154 теста, 139 пройдены, 15 пропущены: 14 Windows-only и один тест настоящего MCP без предоставленного fixture. Это не повторная Windows-проверка.
- 17 статических/упаковочных команд пройдены, включая `tools/check_source.py`, проверку pin-контрактов, Colab, структуры корня и обеих версий реестра.
- Сравнение с Round54 подтверждает неизменность 61 выбранного производственного/исторического файла. Независимая проверка перед опытом подтвердила все 477 привязок файлов, включая 265 файлов исходного кода.

Во время разработки тесты обнаружили гонку создания аварийного таймера, сохранение уже завершённых PID в списке для аварийного завершения и недостаточный резерв для финальных метаданных. Они исправлены до замораживания опыта и покрыты регрессиями. Подборка рабочего примера или численных допусков после результатов не менялась.

## Независимая проверка сохранённого опыта

Повторная проверка без новых вычислений подтвердила все 11 полных результатов и трасс против обоих исторических вызовов, 12 133 записи, формулу и порядок всех 1280 значений, 477 привязок и 58 файлов запечатанного опыта. Арифметика времени, памяти и хранения воспроизведена; итоговый размер сырых материалов опыта — 7 090 038 байт. Первичная проверка самого аудита остановилась из-за несовместимого порядка Path/string в его списке; исправлена только проверка списка, исходные результаты не изменялись. После опыта кратко добавленная ссылка в замороженный индекс документации была удалена с восстановлением его исходных байтов; окончательная проверка всех привязок проходит.

Первая проверка свежераспакованного архива выявила ссылку из отчёта на JSON, который не входит в отдельный исполняемый release-bundle. Ссылка заменена явным указанием пути в полном исходном архиве; состав release-bundle и его проверки не ослаблялись.

## Что дальше

План большого исследования остаётся заблокированным для запуска: этот исполнитель принимает только один фиксированный пример. Следующий необходимый этап — проверяемый адаптер произвольного случая из замороженного протокола, генератор и агрегатор с полным учётом ошибок, затем окончательная фиксация исполнения. Решения о научной пригодности принимаются по будущему исследованию, а не по скорости этого примера. Новый robust-компаратор пока остаётся отдельным проектом методологии.

Точный контракт: [PROSPECTIVE_ADAPTER_CONTRACT.md](PROSPECTIVE_ADAPTER_CONTRACT.md). Машинное резюме: `validation/round55-results.json` в полном исходном архиве. Полные сырые записи, привязки и журналы предоставляются отдельно как `MVS-analyzer-round55-VERIFICATION.zip`; распаковывать их в репозиторий для сборки или CI не требуется. Контрольный отпечаток companion указан в `packaging/SOURCE_MANIFEST.json`.
