# Round37: компактнее корень репозитория

## Что перенесено

По просьбе владельца шесть вспомогательных записей объединены под `plugins/`: четыре каталога исходников в `plugins/sources/`, два готовых пакета в `plugins/packages/`. Файлы поставки находятся в `packaging/`. В исходном Round36 было 17 файлов и 25 каталогов в корне; теперь 15 и 23. Ранее при обсуждении число каталогов ошибочно называлось 29; здесь приведён проверенный подсчёт по ZIP и файловому дереву.

Основное ядро, проекты решения, README, настройки, Windows-ресурсы, безопасность и лицензия не перемещались. Структура расчётов не менялась. Перенос пакетов сохраняет их байты и SHA256; изменены только соответствующие пути в проверке защищённых ресурсов. В исходниках плагинов изменён лишь README пакета отчётов, чтобы его ссылки и пример сборки соответствовали новому месту. Готовые пакеты не пересобирались.

## Что пришлось согласовать

Обновлены ссылки в `docs/PLUGINS.md`, явный список входов сборщика release-bundle и его тесты. Проверка показала, что старый сборщик выбирал только готовый Report Pack, хотя документация перечисляла оба пакета. Теперь оба готовых пакета включены явно; произвольное содержимое `plugins/` не попадает в поставку автоматически.

Первый прогон тестовых макетов после переноса выявил старую относительную ссылку внутри синтетического README. Она исправлена; отрицательный журнал сохранён, затем набор проверок layout выполнен повторно. Это ошибка адаптации тестового макета, не изменение формул или плагинного содержимого.

## Перенос поверх старой рабочей копии

Простой ZIP не убирает старые пути. Точная карта и безопасная процедура находятся в `../packaging/README_RU.md`. Скрипт `tools/migrate_root_layout.py` по умолчанию только проверяет. При `--apply` он требует совпадения старых исходных и новых конечных хешей и переносит старые записи в отдельную локальную резервную папку. Постоянного удаления, правки Git или автоматического коммита нет. Несовпадение, лишнее содержимое, ссылка или конфликт останавливают применение; частичный сбой сохраняет журнал и уже перенесённые оригиналы.

При новой чистой распаковке старых путей нет и перенос не требуется. При наложении на существующий репозиторий нужно проверить изменения и включить удаление старых путей вместе с новыми путями в свой коммит. Резервную папку в коммит не включать.

## Результаты проверки

Команды, результаты и хеши сохранены в `../validation/round37-results.json` и `../validation/round37-evidence.zip`.

- 59 проверок миграции/layout пройдены; те же 59 выполнены с оптимизированным Python (`-O`), без обхода проверок.
- 35 проверок release-bundle пройдены. Сравнение старого/нового bundle подтвердило отсутствие примера в старом комплекте и побайтное сохранение обоих пакетов в новом; синтетический CLI при этом не исполнялся.
- Проверки исходных хешей 43/43, Colab 48/48, UI 18/18 и статические проверки исходника, CLI-контракта и ноутбуков пройдены.
- CLI действительно собран: 0 предупреждений, 0 ошибок. Настоящая Windows-сборка/запуск не выполнялись.
- Все 112 существующих C#-исходников и файлов проектов/решения побайтно совпали с Round36. Авторский README и встроенный Colab-архив также совпали; у пяти защищённых ресурсов сохранились исходные хеши.
- Проверены отрицательные случаи: изменённый/лишний/пропавший файл, другая целевая копия, ссылки, повторный запуск и частичный сбой переноса. Старые оригиналы сохраняются в корне либо резервной папке, а новые установленные файлы не изменяются.

Полный ZIP перед сдачей дополнительно распаковывается в новую папку, где повторяются `check_source`, CLI/ноутбуки, хеши/Colab/UI, release-bundle, миграционные тесты и безопасный dry-run. Удалённый GitHub workflow не запускался. Полный научный benchmark и прежний набор нативных вычислительных тестов не повторялись: вычислительные исходники не менялись.

Научный NO-GO и ожидание настоящего Windows-подтверждения остаются. Уборка не даёт нового основания утверждать статистическую точность или ускорение. Откат исходного layout — полный Round36 плюс сохранённые пользовательские изменения; восстановление из локальной резервной папки выполняется вручную только в свободные пути.
