# Этап26: исправление ошибок присланных Windows-проверок

В обоих присланных логах проверка завершилась с ошибками. После остановки
процесса счётчик его группы уже показывал ноль, но сам процесс ещё не подтвердил
завершение. Код преждевременно возвращал управление. Это воспроизведено двумя
детерминированными тестами до исправления.

Теперь требуется выполнение обоих условий: группа процессов пуста и основной
процесс действительно завершён. Общий предел ожидания остаётся пять секунд.
При превышении сохраняется явная ошибка очистки, а не успешный результат.
Исходная проверка на настоящей Windows не ослаблена.

Две другие ошибки относились к вспомогательному запуску PowerShell для проверки
прав доступа: модуль не загрузился либо процесс превысил время ожидания.
Эта проверка заменена небольшим независимым .NET-инструментом, который только
читает права каталога. Правила защиты каталогов не менялись; требования к правам
и проверка «не исправлять чужие права автоматически» сохранены.

## Что сделать

1. Сделать резервную копию своего Round24 и применить накопительный патч25+26
   после проверки манифеста. Он включает исправление импорта из этапа25.
   README не заменяется. Это патч, не полный проект.
2. Сохранить изменения в своём репозитории обычным способом.
3. В Actions выбрать Manual Windows workflow acceptance и запустить нужный коммит.
   Требуется успех обоих заданий: windows-2022 и windows-2025.
4. Прислать оба архива результатов. В Windows-проверке теперь 21 тест, без пропусков;
   далее должны пройти настоящая калибровка, CLI/workflow и MCP.
5. После успешной CI-проверки выполнить небольшой тест со своим агентом на Windows 11.

Исправление проверено доступными Linux-тестами и компиляцией помощника. Нового
запуска на настоящей Windows здесь пока нет, поэтому поддержка ещё не считается
подтверждённой. Научные формулы не менялись; научный NO-GO сохраняется.

Проверки Linux: из 515 тестов 501 прошёл, 14требуют Windows и пропущены.
Реальный Linux MCP-вызов движка прошёл. Независимая проверка повторила три
новых сценария ожидания и проверку обработки таймаута: 4/4. Помощник ACL
собирается без предупреждений и ошибок; на Linux честно отказывается выполнять
Windows-проверку. Первоначальные неудачи тестов и сборки сохранены в доказательствах.
