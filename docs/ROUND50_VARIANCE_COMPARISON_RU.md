# Round50: где компонентная модель действительно помогает, а где ошибается

## Короткий результат для владельца

Проведено реальное парное сравнение на 192 искусственных наборах: оба существующих метода получали одни и те же исходные измерения. Все 192 пары завершились, недоступных решений не было. Производственный алгоритм не изменён.

- При увеличении различий между объектами компонентная модель обнаружила изменение в 15 из 32 наборов, обычная семья из 12 метрик — в 1 из 32. Это конкретный полезный результат для данного вопроса и заданной модели данных.
- При увеличении разброса повторных измерений внутри объекта оба пути обнаружили изменение во всех 32 наборах.
- При изменении только среднего уровня обычные метрики обнаружили его в 32/32. Компонентная модель проверяет другой вопрос: её 2/32 срабатывания здесь являются ложными выводами об изменении компонентов разброса.
- При одинаковых группах с редкими большими отклонениями компонентная модель дала 5 ложных срабатываний из 32, обычные метрики — 0/32. Поэтому заменять обычный анализ этой моделью по умолчанию нельзя.
- Это небольшая предварительная проверка сильных изменений, а не доказательство готовности MVS для исследовательских выводов. Даже 0/32 ошибок оставляет верхнюю границу 95%-интервала около 10,7%. Общий scientific NO-GO сохраняется.

## Что именно сравнивалось

В каждой группе 16 независимых объектов, у каждого 40 повторных измерений. «Уровень» означает среднее значение. «Внутренний разброс» — колебания повторов одного объекта. «Различия между объектами» — разброс их индивидуальных средних. Смена компонента означает удвоение стандартного отклонения, то есть увеличение соответствующей дисперсии в четыре раза. Это не прежний слабый эффект из большого benchmark.

Первый путь — уже существующий Gaussian VarianceAnalysis.Run: две проверки компонентов с поправкой Бонферрони на две гипотезы, 199 опорных bootstrap-повторов, 100 внутренних повторов оценки характеристик. Второй — существующие наблюдаемые p-значения 12 метрик с Бонферрони на 12. Это не весь процесс калибровки/выбора лучшей метрики; его не следует отождествлять с историческими показателями мощности 14% и 28,8%. Два фиксированных примера заранее подтвердили точное совпадение наблюдаемых полей второго пути с Results, включая недоступность метрики.

Компонентная модель учитывает разные средние групп. Поэтому сравнение сдвига уровня проверяет разграничение вопросов, а не проигрыш модели в задаче, которую она должна решать. Семья обычных метрик не устанавливает, какой латентный компонент изменился.

## Все условия и результаты

| Условие | Компонентная семья | 12 метрик | Внутренний компонент | Межобъектный компонент |
|---|---:|---:|---:|---:|
| Нормальные одинаковые группы | 0/32 | 0/32 | 0/32 | 0/32 |
| Только уровень +2 | 2/32 | 32/32 | 1/32 | 1/32 |
| Только внутреннее SD ×2 | 32/32 | 32/32 | 32/32 | 0/32 |
| Только межобъектное SD ×2 | 15/32 | 1/32 | 1/32 | 15/32 |
| Оба SD ×2 | 32/32 | 32/32 | 32/32 | 17/32 |
| Одинаковые группы, тяжёлые хвосты t5 | 5/32 | 0/32 | 3/32 | 3/32 |

В условии обоих изменений модель обнаружила оба компонента одновременно в 17/32. При изменении только межобъектного компонента одно из 15 семейных срабатываний также ошибочно указало внутренний компонент; внутренний компонент в целом сработал 1/32. В t5-условии каждый компонент сработал 3/32, пересечение — 1/32, объединение — 5/32. Все отказы, даже если бы они возникли, оставались бы в исходных знаменателях 32.

Для межобъектного изменения парные исходы: оба метода сработали 1 раз, только компонентный — 14, только обычный — 0, оба не сработали — 17. Разность долей 43,75 процентного пункта; заранее заданный консервативный точечный 95%-интервал для парной разности [11,54; 64,66] п.п. Интервалы не одновременны для всех условий, победитель по ним не выбирался. Нельзя переносить эту величину на иные эффекты, распределения или исследование владельца.

## Независимые ориентиры

Точные F-ориентиры вычислены в Python непосредственно из сохранённых измерений с SciPy, отдельно от native-модели. Для нормального внутреннего разброса использованы суммы квадратов отклонений внутри объектов и 624 степени свободы в каждой группе. Для межобъектного вопроса F-ориентир допустим только при одинаковом внутреннем разбросе: 15 степеней свободы для дисперсий средних объектов. Он обнаружил межобъектное изменение в 17/32 против 15/32 у bootstrap-модели. Их p-значения не обязаны совпадать: процедуры различны. При неравном внутреннем разбросе и при t5 соответствующие ориентиры помечены неприменимыми, а не выданы за точный контроль.

5/32 на тяжёлых хвостах — предупреждение о зависимости Gaussian-процедуры от предположений; точечный Wilson-интервал [6,86%; 31,75%]. Это не новая проверка или оправдание неудачного эксперимента Round27. Дополнительных наборов после просмотра результата не добавляли.

## Воспроизводимость и стоимость

Число наборов выбрано до их генерации по заранее установленному правилу стоимости: два полных прогона на фиксированной буквальной инженерной таблице, затем ограничение максимум 32 на условие. Все 192 координаты генератора зафиксированы заранее. Отдельная независимая проверка подтвердила стоимость и правило выбора. Затем зафиксированы код, native-библиотеки, runtime, NumPy/SciPy, протокол и семена. Один запуск, без замен неудачных наборов и без повторного поиска результата.

Фактическое время до сериализации результата: 667.63 с, в пределах 900 с. Восемь постоянных однопоточных native-процессов. Суммарный native CPU: 152.91 с; это не CPU Python-координатора. Выборочный пик общей RSS процессов: 523.59 MiB, без установленного лимита памяти. Полные логические свидетельства около 105,9 MB; архивные транспортные копии учитываются отдельно.

Медиана instrumented Run — 19,83 с, наблюдаемых 12 тестов — около 0,00106 с. Это НЕ честное отношение скоростей двух чистых статистических тестов: Run дополнительно строит интервалы и внутренние оценки чувствительности, а журналирование каждой промежуточной операции и передача через Python-потоки входят во время. Инженерная буквальная таблица дала около 1,46 с на Run; её прогноз оказался существенно оптимистичнее фактической оркестрации. Временной бюджет не увеличивали. Общая подготовка данных, каждый этап и native CPU сохранены отдельно; ускорение не заявляется.

## Изменения проекта и пределы

Добавлены только воспроизводимый диагностический harness, независимый генератор/ориентиры, проверка сохранённых результатов и документы. Производственные Core/Infrastructure/Benchmark/python/src и README сохранены без изменений. Ни новый тест, ни Math.NET, ни ранее не прошедший max-rank не активированы. Исторические отрицательные результаты сохранены.

Вывод для дальнейшей работы: компонентный путь действительно отвечает на полезный вопрос, который семья ранговых метрик может пропускать. Главный ограничитель теперь конкретный — устойчивость компонентного вывода при ненормальных данных и строгая видимость его предположений. Следующая работа должна разбирать этот ограничитель с отдельным фиксированным протоколом, а не добирать удачные семена или объявлять текущую модель универсальной.
