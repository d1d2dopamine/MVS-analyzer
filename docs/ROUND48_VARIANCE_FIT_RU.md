# Round48: независимая проверка разложения разброса

## Что получилось

Существующий расчёт, который отдельно оценивает разброс измерений внутри объекта и различия между объектами, выдержал заранее заданную проверку: 18 численных случаев и два случая полностью постоянных данных. Обнаруженной ошибки, которую следовало бы исправить в рабочей формуле, нет.

Это полезный следующий шаг после Round47: ранговое сравнение не всегда чувствительно к симметричному расширению распределения. В MVS уже есть отдельная модель компонентов разброса. Прежде чем обсуждать её применение к такой задаче, проверили, правильно ли она решает собственную задачу оценивания.

Улучшение этого этапа — воспроизводимая независимая проверка и защита от будущих регрессий. Вычисления рабочего движка не изменены, прирост мощности обнаружения не измерялся. Общий научный статус NO-GO сохраняется: нельзя объявлять MVS полностью проверенным инструментом для исследовательских выводов.

## С чем сравнивали

Фиксированные входы, пределы ошибок и бюджет записаны до расчётов в ROUND48_VARIANCE_FIT_PROTOCOL.md и variance-fit-fixtures-v1.json. Было ровно 20 вызовов настоящего VarianceAnalysis.Fit, без повторного подбора примеров или допусков.

1. Сбалансированные примеры имеют аналитический ответ. Внутренний разброс равен 4; межобъектный — 1 для ML и 1,5 для REML. Различие связано с двумя заранее существующими способами оценивания.
2. Пример с нулевым межобъектным компонентом проверяет границу модели. Движок использует малый положительный численный предел; его не выдавали за буквальный ноль.
3. Несбалансированные группы проверены отдельным расчётом полной матрицы ковариации, GLS-средних и ML/REML-правдоподобия. Он не копирует профильную формулу из движка.
4. Проверены ограничения равенства компонентов, девять сдвигов/масштабирований, смена знака, вложенность моделей и три отношения правдоподобий.
5. Постоянные данные должны возвращать предусмотренный неуспех с неопределённым правдоподобием, а не убедительный фиктивный результат.

Независимый расчёт использует SciPy и отдельную 60-значную проверку mpmath. Четыре намеренно плохо обусловленные матрицы показывают, почему одного обычного double недостаточно: его относительная ошибка определителя достигла примерно 3,8×10⁻⁷, тогда как многозначная проверка согласуется с точным тождеством лучше 10⁻⁵¹. Это свойство проверки матриц, а не найденная ошибка рабочего Fit.

## Численный результат

- Все 18 регулярных оценок и оба защитных случая прошли фиксированные требования.
- Максимальный проигрыш значения целевой функции независимому решению: 1,14005×10⁻⁷ при допуске 2×10⁻⁵.
- Максимальная ошибка параметра использовала 53,1% его заранее установленного допуска.
- Максимальное расхождение трёх отношений правдоподобий: 1,53807×10⁻⁷ при допуске 10⁻⁴.
- Все девять преобразований данных прошли проверку единиц измерения и нормировки.
- Независимый расчёт выполнил все 64 фиксированных старта: 1514 вычислений цели, 13 многозначных вычислений, около 0,767 секунды. Один процесс с 20 Fit занял около 0,191 секунды. Это стоимость проверки на данной Linux-машине, не сравнительный тест производительности приложения.

## Проверки и воспроизведение

Новый Python-набор содержит 21 тест самого проверяющего инструмента. Native-проба отвергает десять некорректных входов до первого Fit; Release-сборка прошла без предупреждений и ошибок. Полные исходные результаты, неудачные старты оптимизатора и точные идентификаторы файлов сохранены в отдельном RAW-EVIDENCE архиве Round48.

Из корня проекта после установки validation/requirements-rank-reference.txt:

```sh
dotnet build validation/variance_fit_reference/VarianceFitReference.csproj -c Release
python validation/variance_fit_reference.py --root "$PWD" --out /tmp/mvs-variance-new-run --native-command "$(command -v dotnet)" "$PWD/validation/variance_fit_reference/bin/Release/net8.0/MvsAnalyzer.Core.Tests.dll"
```

Выходная папка должна быть новой: инструмент не перезаписывает предыдущие результаты. Возврат 0 означает прохождение этой проверки, 1 — численное расхождение, 2 — некорректные доказательства или неопределённый эталон. В CI добавлена та же ограниченная проверка с сохранением результатов при любом исходе.

Независимая повторная проверка сохранённых результатов отдельной матричной реализацией подтвердила вывод. Максимальное расхождение сообщённого движком правдоподобия с прямым пересчётом: 7,11×10⁻¹⁴; все привязанные исходники и результаты совпали по отпечаткам. Новых Fit или оптимизаций для этого аудита не выполнялось.

Общая локальная регрессия: 688 validation-тестов, из них 684 выполнены и 4 пропущены из-за отсутствия внешних native-артефактов; Python API: 154 теста, 139 выполнены, 14 Windows-only и один настоящий MCP/native fixture пропущены. Эти пропуски не заменяют Windows-проверку. Полный Core-набор заново не запускался: производственный код не менялся. Новый численный native-путь реально выполнен, а не пропущен.

## Границы вывода и следующий вопрос

Согласие нескольких стартов на несбалансированных примерах не доказывает глобальную оптимальность для всех возможных данных. Здесь не проверены статистическое покрытие интервалов, частота ложных срабатываний, мощность, устойчивость к ненормальным данным или весь bootstrap-путь VarianceAnalysis.Run. Нельзя переносить этот PASS на прежние неудачные эксперименты Round27/32/46.

Следующий содержательный вопрос — корректность собственного теста компонентов разброса: как его ограниченная и свободная модели, bootstrap и граничный нулевой компонент связаны с заявленным нулём. Это отдельная проверка существующего пути, прежде чем предлагать его как альтернативу ранговому сравнению.

README и все рабочие формулы остаются прежними. Исторические необязательные RAW-архивы остаются в прежних отдельных вложениях; SOURCE_MANIFEST.json сохраняет их точные ссылки и отпечатки файлов. Отпечаток (SHA-256) нужен, чтобы проверить, что файл не изменился.
