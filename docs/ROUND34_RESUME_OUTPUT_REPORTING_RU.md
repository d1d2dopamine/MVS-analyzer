# Round34: видимые файлы после ошибки возобновления

## Исправление ошибки CI

По присланной ошибке `Embedded Colab source is stale/missing` дополнительно восстановлен актуальный встроенный архив `Assets/colab-cli-source.zip`. Он заново создан штатным детерминированным генератором из текущих исходников. Точная команда `python tools/check_source.py` после этого проходит. В старом архиве было 11 устаревших файлов и отсутствовали два файла интерфейса записи; новый архив содержит все 48 зарегистрированных исходных файлов и собственный манифест. Исторические пины не ослаблялись: они не участвуют в этой команде. Это отдельная ошибка комплектации исходного ZIP, а не ошибка ваших действий с коммитом.

## Что исправлено в возобновлении

Если возобновлённый расчёт успел сохранить часть результатов, а следующий файл записать не удалось, CLI теперь сообщает, какие файлы действительно сохранились и проверены. Ошибка по-прежнему остаётся ошибкой: частичный набор файлов не превращается в успешно завершённый результат.

До изменения ошибка воспроизведена на настоящей незавершённой контрольной точке калибровки. После восстановления были записаны корректные `calibration_state.json` и `calibration.csv`, затем запись `calibration_tracks.csv` столкнулась с заранее созданным каталогом. Старое машинное сообщение возвращало пустой список файлов и `outputDirectory: null`. Контрольная точка на входе осталась неизменной. Это проверка движка возобновления вместе с машинным сериализатором; синхронный тестовый обработчик прогресса создаёт препятствие без гонки по времени.

Исправление распространяется на возобновление калибровки, анализа, анализа дисперсии, оценки и MELSM. Перед первым выходным файлом начинается наблюдение; каждый файл попадает в успешный список только после завершённой записи и проверки размера/хеша. Неудавшаяся запись помечается как неопределённая. Старые файлы из каталога не принимаются за новые результаты.

## Что важно при использовании

- Наличие частичных файлов не означает, что весь расчёт или экспорт завершён. Не используйте такой каталог как полный успешный набор результатов.
- Это не транзакция из нескольких файлов: уже записанные файлы не откатываются, а неудачно перезаписанный файл может быть повреждён.
- Сообщение описывает состояние на момент проверки. Последующее изменение файла другим процессом оно не предотвращает.
- Возобновление бенчмарка и архивный настольный интерфейс пока сохраняют прежнее поведение без нового наблюдателя.
- Статистические методы, случайные последовательности, порядок восстановления, правила доверия к кешу и история вычислительной среды не менялись. Научный статус NO-GO прежний.

## Проверки

Полный протокол и сырые данные включены в `validation/round34-evidence.zip`; машинная сводка — `validation/round34-results.json`.

Проверки восстановления выполняются с включёнными резервными копиями в изолированном каталоге. Отключение резервных копий обошло бы нужный путь восстановления. Для сравнения времени используются отдельно обозначенные синтетические завершённые контрольные точки: это сравнение чтения кеша и экспорта, а не повторная проверка научной точности.

## Уже известное ограничение тестов

Дополнительный старый Colab-тест дал **47/48** и в неизменённом Round33, и в Round34. Причина первого расхождения — устаревший контрольный SHA файла `Benchmark/BenchmarkDatasets.cs`: файл был осознанно изменён ещё в Round25, когда хеш стали брать из тех же байтов, которые импортированы. В историческом наборе обнаружены 17 несовпадающих пинов из 30. Их нельзя автоматически заменить текущими хешами: каждый требует сверки с историей изменений. В этом этапе пины не переписаны; оба отрицательных результата сохранены. Ранее успешные общие Python-наборы не включали этот дополнительный Colab-тест.

Реальные Windows-проверки здесь не выполнялись. Для исправленного Windows MCP по-прежнему нужен запуск `Manual Windows workflow acceptance` на вашем коммите и отдельная проверка на вашем Windows11.

## Откат

Сохраните свою рабочую копию. Для отката верните полный Round33 и пересоберите проект, не смешивая DLL разных версий. Пользовательские входные файлы и контрольные точки не нужно удалять или переписывать. README в полном архиве сохранён без изменений.

## Прозрачность сравнительного измерения

Первая серия из 30 попыток выявила ошибку самого измерительного инструмента: точный JSON-парсер возвращал десятичный тип для интервала наблюдения, несовместимый с ожиданием потока. Защитный обработчик остановил дочерние процессы и дождался их завершения; все 30 отрицательных исходов сохранены. По ним нельзя судить ни о времени успешной работы, ни о совпадении результатов.

Перед повторной полной серией исправлена только конвертация временных ограничений на границе системного ожидания. Добавлены проверки с реально разобранным планом. Первоначальные план, программа, хеши и результаты сохранены отдельно; повторная серия имеет новое явное дополнение к плану. Порядок всех пяти заданий, три пары AB/BA/AB, исходные контрольные точки и численные настройки прежние. Отдельные удачные наблюдения не выбирались.

В новом инструменте главный поток блокируется до завершения конкретного процесса и сразу фиксирует время; независимый поток ограничивает время и память. Поэтому в измерение не добавляется прежняя задержка опроса завершения до 50 мс. Это не исправляет задним числом старые измерения Round31/33.
