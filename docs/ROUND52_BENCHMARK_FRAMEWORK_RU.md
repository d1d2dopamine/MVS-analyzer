# Round52: версионированная система бенчмарков MVS

## Результат

Создан MVS Benchmark Suite 1.0.0: реестр восьми проверок и сравнений с английскими названиями, академическая спецификация и воспроизводимая таблица 96 наблюдений из уже сохранённых результатов. Новых научных выборок, модельных расчётов или запусков NIST на этом этапе не было. Мощность, частота ложных срабатываний и производственные алгоритмы не изменены.

Каноническое описание для рецензирования: [BENCHMARK_SUITE.md](BENCHMARK_SUITE.md). Таблица свидетельств: [BENCHMARK_RESULTS_RU.md](BENCHMARK_RESULTS_RU.md). Машиночитаемый реестр: `validation/benchmark-suite-v1.json` в полном исходном архиве; отдельный runtime-bundle не содержит validation-инструменты.

## Что именно стало проверяемым

Каждое численное наблюдение связано с точным файлом результата, его SHA-256 и JSON-путём. Для долей отдельно закреплён исходный запрошенный знаменатель. Проверка отвергает изменённый файл, неверный указатель, подменённый знаменатель, неизвестный статус, выход за каталог и попытку назвать старое исследование независимой валидацией. Сгенерированная таблица должна точно совпадать с реестром; это теперь отдельный шаг CI.

Указаны цели, генераторы данных, оцениваемые параметры и нулевые гипотезы, методы, показатели качества, неопределённость, отказы, остановка и ограничения сопоставимости. Общего победного балла нет. Исторический MVS-BENCH-1.2.0 сохраняет прежнюю идентичность и NO-GO. Его 5490 рабочих единиц состоят из 5370 строк повторений и 120 строк устойчивости; это не доказательство наличия 5490 независимых наборов данных.

NIST StRD используется как основа будущих численных эталонов. Найдены только два прямых соответствия имеющимся операциям: среднее и выборочное стандартное отклонение с делителем n−1 под корнем. Их статус — mapped_not_run. Четыре остальные категории отмечены unsupported. Ни одного нового результата NIST или сертификации MVS не заявлено. ADEMP используется как структура планирования, а не как готовый набор данных или знак качества.

## Как читать существующие результаты

Round50 сравнивал два уже существующих метода на 192 фиксированных моделируемых наборах. Для увеличения межобъектного разброса результат был 15/32 против 1/32; для t5-null — 5/32 против 0/32. Это малый разработочный пилот с существенной неопределённостью и предупреждением о чувствительности гауссовского метода к предположениям. Он не является улучшением производственного алгоритма или новым результатом прежнего MVS-BENCH-1.2.0.

Сохранены отрицательные исходы Round27 и Round32, ухудшение повторяемости Round46 и его первоначальный технический отказ с отдельным последующим аудитом. Численная проверка Fit, проверка программного контракта и проверка статистической применимости имеют разные статусы. Независимый пересчёт сохранённых свидетельств не создаёт независимую научную выборку.

## Выполненные проверки

- Новый валидатор: 32 теста; дополнительно 11 искажений действительного реестра отвергнуты.
- Общий validation: 778 тестов, 774 пройдены, 4 проверки внешних native-свидетельств пропущены из-за отсутствия заданных путей к этим отдельным запускам. Discovery их не запускает автоматически.
- Python: 154 теста, 139 пройдены, 15 пропущены: 14 требуют Windows, один требует отдельного native-MCP fixture.
- Все 17 локальных команд проверки исходников, CLI, архивов, source pins, Colab, структуры, notebooks и нового реестра завершились с кодом 0.
- 47 файлов производственного Core/Infrastructure/Benchmark/Python и README побайтово совпадают с доставленным Round50. Включены ранее подготовленные восемь точных алгебраических проверок моментов Round51; они не являются новым моделированием мощности.

Повторный запуск Windows и производственных научных бенчмарков для этого изменения не выполнялся. Локальная успешная проверка CI-команд не означает, что удалённый GitHub workflow уже выполнен на этой версии.

## Ограничения и следующий этап

Реестр зарегистрирован ретроспективно. Он делает доказательства и пробелы обозримыми, но не исправляет задним числом план исследования. Некоторые полные исходные данные и журналы находятся в ранее доставленных дополнительных RAW-архивах; они не требуются для сборки и текущего валидатора. Объединённый хеш всех независимых наборов не придуман: там, где он не установлен, оставлен null с объяснением.

Следующий ограниченный численный этап: заранее зафиксировать адаптер прямых векторов NIST, точные сертифицированные поля, оригинальные файлы и хеши, диапазон трудностей и допуски, затем выполнить сравнение среднего и sample SD. Любая новая проверка устойчивости статистического метода требует отдельного ADEMP-протокола с обоснованием точности Монте-Карло и бюджета. Научный NO-GO остаётся действующим.

## Проверка упаковки

Первая проверка свежераспакованного архива обнаружила две новые ссылки документации на validation JSON, отсутствующий в отдельном runtime-bundle. Ссылки заменены явными путями полного исходного архива с описанием границы поставки; проверка ссылок не ослаблена. Исходный журнал отказа сохранён в дополнительных свидетельствах. После исправления полный набор команд повторён на новом свежем извлечении.
