# Этап 23: MCP для Windows, с открытым требованием реальной проверки

## Что сделано

Добавлен экспериментальный Windows-backend общего workflow/MCP. Он рассчитан на
Windows 10+ x64, включая Windows 11, и локальный фиксированный диск NTFS.
Подробная установка и объект настройки локального агента находятся в
[ROUND23_WINDOWS_MCP.md](ROUND23_WINDOWS_MCP.md).

- Native CLI получил явный `MVS_APPDATA_ROOT`: журнал, плагины, настройки и связанные
  каталоги перенаправляются внутрь конкретного запуска. При отсутствии переменной
  прежнее поведение сохранено. Windows-обёртка требует новую capability движка;
  старый CLI не запускается для анализа с ложным предположением об изоляции.
- Блокировка workspace использует постоянный эксклюзивный файловый handle.
  Записи публикуются без замены существующих, входные snapshots не перезаписываются.
- Новый workspace создаётся с закрытым ACL текущего пользователя и SYSTEM.
  Чужие/широкие разрешения существующего каталога не меняются автоматически:
  нужно указать новый, ещё не существующий путь.
- Проверяются NTFS, junction/reparse, UNC, ADS, имена устройств, неоднозначные
  окончания имён и другие неподдержанные пути. Ограничение полного пути: менее
  248 символов. Это проверка в доверенной локальной среде, не защита от владельца
  компьютера или администратора, переписывающего файлы.
- Native-процесс создаётся сразу внутри собственного Job Object. Отмена Windows
  принудительно завершает его дерево; частичные результаты сохраняются. Отсутствие
  конечной квитанции означает неизвестное/прерванное состояние, без автоматического
  повтора. Таймаут cleanup возвращается как ошибка, а не успех.
- Исправлена совместимость JSON-вывода с Windows codepage: workflow CLI явно пишет
  UTF-8, включая кириллицу и другие Unicode-символы.

Научные вычисления, формула, 12 активных метрик, Bonferroni и научный NO-GO не
изменялись. Изменение Core/Models касается только пути настроек. Локальная frozen
запись не удостоверяет предварительную регистрацию или отсутствие просмотра данных.

## Что действительно проверено

Проверки выполнялись в Linux/cloud:

- 148/148 нативных тестов; сборки CLI/Core.Tests без предупреждений и ошибок.
- Python: 512 найденных тестов, 498 пройдено, 14 Windows-only пропущено явно.
  В том числе общая workflow suite: 39/39; реальная MCP/native-проверка включена.
- Реальные CLI/MCP-запуски: сохранение старых научных результатов и полей, native
  diagnostic exit 2, exploratory/frozen, повтор без нового вычисления, отказ при
  изменении привязанной к протоколу калибровки, проверка артефактов.
- Сборка wheel, установка, обе команды help и анализ через установленный пакет.
- Проверки исходников, CLI-контракта, embedded source payload, notebooks и ссылок.
- Независимые Python reference checks являются проверками своих эталонов;
  сопоставление с тем же native-движком не является независимой научной валидацией.

**На Windows эти тесты ещё не исполнялись.** Ни Windows Server CI, ни реальная
установка у агента Windows 11 здесь не объявляются успешными. Полный научный benchmark
не повторялся: научный алгоритм не менялся, прежний NO-GO остаётся действующим.

## Как завершить Windows-проверку

1. Сохранить предыдущий Round22 для отката, затем внести Round23 в свой репозиторий.
2. В Actions открыть **Manual Windows workflow acceptance**, выбрать нужную ветку
   и запустить вручную. Матрица проверит windows-2022 и windows-2025.
3. Получить оба архива проверок. Win32-suite требует ровно 18 тестов и ноль пропусков;
   all-skipped не считается успехом. Проверяются ABI, ACL, журнал/пути, конкурирующие
   записи и блокировки, дочернее дерево, смерть координатора, реальные native/MCP.
4. После успешной проверки сделать маленький синтетический stdio-запуск из своего
   агента на Windows 11. Серверные CI runners не заменяют этот последний smoke.

Коммиты, push, запуск удалённого CI и публикация с нашей стороны не выполнялись.
Архив содержит исходники, ручной workflow, инструкции и свидетельства Linux-проверок.
Новые данные исследования, инструментарий и большие корпуса в архив не входят.

## Риски и откат

Изменения сделаны в отдельной копии Round22. Для отката использовать прежние
исходники/сборку и прежнюю конфигурацию агента; новые workspace оставить как evidence,
не перезаписывая их. Native-переменная opt-in, обычный CLI сохраняет прежние defaults.
Windows Job/ACL/NTFS-ветки требуют проверки на реальном OS. Долговечность при потере
питания, недоверенный владелец машины, сетевые диски и macOS workflow не подтверждены.

В процессе review найдены и исправлены два интеграционных риска: необработанный
TimeoutExpired при cleanup и зависимость machine JSON от кодировки stdout. Их
регрессии включены. Упаковка single-file self-contained не используется в Windows
gate: размер одного файла может превысить существующий лимит хеширования 64 MiB;
инструкция использует multi-file publish, а не ослабление проверки.

Финальный installed-wheel smoke до последней правки вернул `unsafe_path`, хотя native
успел сохранить анализ. Остаточных специальных файлов не найдено. Отдельным
детерминированным примером воспроизведён дефект сканера квоты: временный файл,
исчезнувший после перечисления, давал `is_file=false` и `is_dir=false` и ошибочно
считался специальным. Точное имя исчезнувшего файла в исходном smoke не записано,
поэтому причинная связь с тем конкретным запуском остаётся обоснованной гипотезой.
Исправление использует один `lstat` и пропускает только `FileNotFoundError`;
существующие symlink/special files по-прежнему отклоняются. Неуспешная квитанция и
артефакты сохранены, новый installed-run использует другой workspace. Повторные
проверки выполнялись после исправления. Первая попытка сборки wheel также не
прошла из-за отсутствия setuptools в runtime-venv; сборка выполнена установленным
build-интерпретатором, затем wheel установлен и проверен по байтам исходников.
