# Этап31: расчёт получает собственный канал сохранения

## Что изменилось

Раньше пять расчётных маршрутов сами открывали конкретный файловый механизм резервных копий. Поэтому проверить, например, отказ записи после третьего шага без настоящего диска было трудно: вычисление и способ сохранения были связаны напрямую.

Теперь калибровка, анализ сводных показателей, анализ дисперсии, исследование оценивания и MELSM могут получить отдельный объект записи на конкретный запуск. Он умеет прочитать сохранённый шаг, записать новый и отметить завершение. Расчёт владеет этим объектом и закрывает его один раз. Оптимизатор получает тот же объект взаймы и не закрывает его за владельца.

Обычные вызовы продолжают использовать прежние резервные копии. Их сигнатуры, настройки и поведение сохранены. Новый механизм подстановки не хранится в общей изменяемой переменной: один тест или запуск не может незаметно заменить его для другого. При этом прежний контекст стандартного механизма резервных копий остаётся на месте; полной независимости всех частей приложения от файлов здесь ещё нет.

## Практическая польза

Можно отдельно проверить отказ открытия, чтения, записи и завершения, отмену, закрытие и вложенный запуск. Это облегчает будущие изменения хранения: проверка вычислений больше не обязана воспроизводить каждый сбой настоящего диска. В тестах сохранённые данные копируются через сериализацию, чтобы случайная общая ссылка на массив не скрывала ошибку.

Это улучшение архитектуры и проверяемости. Формулы, случайные выборки, порядок вычислений и научные критерии не менялись. Экспериментальный метод этапа27 по-прежнему не прошёл свой критерий продолжения; новые научные выборки здесь не запускались.

## Проверки и ограничения

Итог выполненных проверок: 195 из 195 нативных тестов прошли. В Python наборах обнаружено 536 проверок: 522 прошли, 14 проверок настоящего Windows ожидаемо пропущены на Linux. Проверка обмена MCP с заново собранным настоящим Linux-движком прошла. Сборка CLI завершилась без ошибок и предупреждений. Шесть новых групп проверок отдельно повторены независимо. Внешнее сравнение дало 78 совпадений базового и нового вариантов, 54 проверки явной подстановки/повторного чтения и 360 совпадений во время замеров. Машиночитаемые результаты приведены в validation/round31-results.json. Сравнение с этапом30 охватывает шесть вычислительных маршрутов, сообщения о ходе работы и содержимое резервных копий, включая отмену и продолжение. Из сравнения исключаются только заранее перечисленные служебные поля. Замеры времени описывают эти конкретные нагрузки и не доказывают общего ускорения.

Исправления восстановления этапов29–30 сохранены. Их гарантия касается повторного использования значений целевой функции симплексного оптимизатора; она не означает, что любое сохранённое готовое научное заключение заново пересчитывается. Проверка настоящего Windows-движка остаётся отдельным незавершённым условием.

Поставка накопительная и требует пересборки. Сохраните копию проекта перед применением; README не заменяется. Для отката верните исходники этапа30 и пересоберите все используемые компоненты.

Отдельная записка NUMERICAL_LIBRARY_REUSE_ASSESSMENT_RU.md объясняет, где разумно использовать зрелые математические библиотеки. Зависимости и численные методы в этом этапе не заменялись.
